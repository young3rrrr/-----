# Використання PlantUML замість Mermaid для побудови діаграми прецедентів (Use Case)

## Контекст та постановка проблеми
Під час першої ітерації генерації концептуальної моделі прецедентів (Ітерація 1) інструментом моделювання було обрано Mermaid. 
У результаті аудиту згенерованих артефактів було виявлено, що синтаксис Mermaid не має нативної семантики для Use Case діаграм. Інструмент реалізує їх через абстрактні блок-схеми (`flowchart`), де актори моделюються як прямокутники з емодзі, а зв'язок узагальнення (`generalization`) реалізується звичайною стрілкою потоку з текстовою міткою замість канонічної стрілки наслідування UML. Це призвело до порушення стандарту нотації UML 2.5 та низької читабельності діаграми (перетин зв'язків).

## Фактори впливу на рішення (Decision Drivers)
* **Відповідність стандарту UML 2.5:** наявність канонічних піктограм акторів (stick figures), овалів прецедентів та стрілки наслідування з незафарбованим трикутником (`<|--`).
* **Чіткість відображення зв'язків:** підтримка декларативних стереотипів `<<include>>` та `<<extend>>` без візуального захаращення ліній.
* **Автоматична оптимізація компонування (Auto-layout):** мінімізація перетину ліній залежностей між акторами та прецедентами.

## Розглянуті варіанти
1. **Збереження Mermaid з оптимізацією стилів:** спроба ручного вирівнювання через CSS та приховані зв'язки.
2. **Перехід на PlantUML (`.puml`):** використання спеціалізованої мови моделювання діаграм UML.

## Результат рішення
Обраний варіант: **«Перехід на PlantUML»**. 
Ми відмовляємося від використання Mermaid для діаграм використання на користь PlantUML. PlantUML нативно підтримує метамодель UML Use Case, забезпечує коректну візуалізацію акторів, правильні стрілки узагальнення та чітке структурування меж системи (`rectangle OpenCRM`).

### Наслідки (Consequences)
* **Добре:** повна відповідність стандарту UML 2.5: правильні символи акторів, прецедентів, зв'язків наслідування та стереотипів `<<include>>` / `<<extend>>`.
* **Добре:** висока читабельність діаграми завдяки вбудованому рушію компонування Graphviz/PlantUML без перетину стрілок.
* **Погано:** рендеринг PlantUML вимагає наявності Java/Graphviz або звернення до сервера рендерингу PlantUML на відміну від вбудованого в браузер Mermaid.

## Плюси та мінуси варіантів

### Варіант 1: Mermaid
* **Добре:** вбудована підтримка у GitHub Markdown за замовчуванням.
* **Погано:** відсутність нативного синтаксису Use Case; генералізація є фіктивною стрілкою; актори виглядають як прямокутні блоки процесу.

### Варіант 2: PlantUML
* **Добре:** галузевий стандарт для UML-діаграм, нативна підтримка всіх елементів Use Case.
* **Добре:** чистий, декларативний код і професійний вигляд графічного рендеру.
* **Погано:** потребує зовнішнього процесу генерації графічних файлів (.png).
